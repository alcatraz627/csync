[PLANNED] Notes will also hold Pins for URLs and text snippets. A Pin can have an optional title, tags, and description. Notes, Pins, images, media, and files need the same Android Sharesheet egress and typed csync share ingress. A received item should retain its URI grant and identity when csync itself is chosen from Android Share.

The routing test is circular: select an item inside csync, share it through Android, choose csync again, then choose a supported destination such as Pi screen, Notes, Pins, Chat, or a named device. The same capability decision must drive the inline menu and the incoming share surface. Actions remain additive. The item type and source determine which actions are supported; neither entry path may silently drop a valid action. The owner marked the Pin list and picker as later work, so this is a contract and acceptance test, not a claim that the current clickthrough or Android app implements Pins.
