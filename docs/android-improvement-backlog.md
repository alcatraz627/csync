# Android improvement backlog

This list records the owner's requested Android work and the acceptance needed before calling each item complete. The media reliability and casting defects take priority over visual changes.

| Work | Current state | Acceptance |
|---|---|---|
| Casting and streaming reliability | Open. The owner reports slow starts and frequent non-playback across cast/stream routes. The Pi has active undervoltage. One false player-state defect was reproduced and corrected. | Exercise representative Pi-file, phone-stream, phone-file cast, and YouTube routes on the real phone and screen. Record startup delay, buffering, failure code, visible video, sound, and pause/stop response. |
| Direct YouTube app share | Open. Version 2.11 accepts one YouTube URL within shared title text. Emulator share intent → csync chooser → Pi player → Stop passed with a real muted Pi stream. A native YouTube-app tap and sustained screen playback remain unconfirmed. | In YouTube, tap Share → csync → Play on Pi screen. Show the selected title, muted startup, visible picture, seek/pause/stop, and a useful error for blocked content. No manual URL paste. |
| Whole-app UI and mini player | Open. The first ten-screen mock was rejected by the owner. A second task-led direction and real emulator screenshots are in `docs/android-ui-direction-2.md`; this is a proposal, not an accepted design. The working app still has oversized Media buttons. | Inspect dark and alternate-accent themes, narrow and large-font layouts, get owner feedback, then implement and visually test the accepted direction. A mini player exposes target, state, pause/resume, Stop, and full controls. |
| UI design system | A [proposal](android-ui-system.md) now audits the shipped layouts and styles and supplies screen jobs, tokens, primitives, variants, composites, and drift checks for mock critique. Check light/dark themes, font scaling, and behavior parity on the installed app. |
| Android widgets and quick actions | Requested. | Launcher icon / favicon | Requested. | Audit current app icon, notification icon, widget branding, and any web favicon; present distinct options that work at small sizes and in light/dark contexts, then install and inspect on the phone. |
